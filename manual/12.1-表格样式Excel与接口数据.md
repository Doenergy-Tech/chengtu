# 12.1 表格的样式、Excel 与接口数据

[返回表格](12-表格.md)

在列卡下方添加条件样式。选择「比较方式」及「条件值类型」，再输入比较值。数字直接填数字，例如 80，布尔选择是或否，文字填待匹配文字。分别选择背景颜色和文字颜色，「条件图标文字」可留空，也可填 ⚠。例如在温度数字列设置大于 80 的条件，将背景选成浅红。排序和筛选后检查颜色仍对应正确数据。

展开「Excel导入 / 导出」。先选择不超过 10 MiB 的 XLSX 文件，再从「Excel工作表」下拉框选择工作表。第一行作为表头，正文最多 10000 行和 100 列。「替换为工作表数据」替换草稿中的列和初始数据，确认后生效。树表先关闭树形模式，绑定数据、列或合并时不能直接替换。「导出Excel文件」保存当前列、数据和正文合并。支持有限的数字公式，导入复杂公式后核对计算值。

展开「接口动态数据（HTTP / WebSocket）」，先在数据接入配置地址和响应，再让表格绑定数组变量。响应路径应指向对象数组，例如 `{"data":[{"temperature":25}]}` 对应 `/data`，列字段填 `temperature`。新增映射用空数组作为回退，等待、断线或过期时不会用示例数据代替。每次接口刷新替换整个数组。

分页由已接入的表格数据服务提供。服务返回当前页的 `rows` 和总记录数 `total`，默认每页 100 行，可选 25、50、100、200 或 500。使用服务端分页时，请先关闭树形模式并移除合并单元格。若接口报响应行数与总记录数不一致，检查同一查询条件下的分页和统计逻辑。刷新接口和提交单元格编辑是独立行为，数据接入本身不会把本地编辑写回服务器。

生产宿主若要允许分页单格编辑，需要同时提供分页读取与写入服务，并为每条记录提供稳定的 `id`。分页响应的 HTTP `ETag` 是当前查询数据版本；写入使用 `PATCH`，请求体如 `{"id":"device-1","field":"temperature","value":26}`，请求头 `If-Match` 带读取时的 ETag。成功响应须返回新的 ETag，表格随后重新加载当前页；若数据已变化，服务返回 412，编辑框保留输入，重新加载后再编辑。缺少写入服务时分页保持只读。当前远端模式只支持单格提交，跨格粘贴、批量清除和撤销重做不会写入服务器；服务端须自行校验用户、租户、记录、字段和值，并按查询条件执行排序和筛选。正式业务接口、鉴权和持久化须由部署宿主提供。

可编辑分页会拒绝缺失或重复的记录 ID。换页或刷新一开始就清空上一页的显示；请求失败时保持空表并提示加载失败，避免旧记录误显示在新页。修正服务响应后点击「重新加载数据」恢复。

数字列公式现支持 A1 引用、四则和幂运算、比较、`IF`、`IFERROR`、`SUM`、`AVERAGE`、`MIN`、`MAX`、`COUNT`、`PRODUCT`、`MEDIAN`、`ABS`、`INT`、`SQRT`、`POWER`、`MOD`、`ROUND`、`ROUNDUP`、`ROUNDDOWN`。`IF` 和 `IFERROR` 只计算所选分支。导入后仍须核对公式；跨工作表、文字/日期函数、查找函数、动态数组以及 Excel 全部计算语义尚不支持。大表格分页验收使用本机合成的百万行总数、每页 100 行，画布与辅助节点只覆盖视口；目标设备、真实接口和 NVDA/JAWS/VoiceOver 读屏器仍须单独验收。

逻辑公式还支持 `TRUE`、`FALSE`、`AND`、`OR`、`NOT`。例如 `=IF(AND(A1>0,B1>0),1,0)` 在两个数字都大于零时返回 1；布尔结果在数字列以 1 或 0 显示。百万行合成服务已完成 50 次跨页读取，辅助节点数量保持在视口范围内；它不能代替真实数据库的查询耗时和长时间内存测试。

### 服务端接入示例

宿主服务可引用 `packages/advanced/table-http-server.mjs` 的 `createTableHTTPHandler`。创建时必须指定允许的页面来源、固定表 ID、可编辑字段、`authenticate` 和 `repository`：

```js
import {createTableHTTPHandler} from './packages/advanced/table-http-server.mjs';
import {createTableHTTPUpstreamRepository} from './packages/advanced/table-http-upstream.mjs';

const tableRepository = createTableHTTPUpstreamRepository({
  pageURL: 'https://business-api.example/devices/page',
  editURL: 'https://business-api.example/devices/cell',
  headers: async ({identity}) => ({
    Authorization: await serverSideTokenFor(identity.tenantId)
  })
});
const handler = createTableHTTPHandler({
  origin: 'https://your-product.example',
  tableId: 'devices',
  columns: [
    {key: 'id', type: 'text', readOnly: true},
    {key: 'name', type: 'text'},
    {key: 'temperature', type: 'number'}
  ],
  authenticate: async (request, {action, tableId}) => {
    // 宿主验证会话及该用户对本表的 read/edit 权限。
    // 成功返回 {tenantId, userId}，拒绝返回 null。
    return verifyTableSession(request, action, tableId);
  },
  repository: tableRepository
});
```

`createTableHTTPUpstreamRepository` 在 `packages/advanced/table-http-upstream.mjs`。它以服务端配置的地址请求业务 HTTP 接口：分页 POST 透传受校验的查询对象，单格 PATCH 发送 `{id,field,value}` 和 `If-Match`；上游分页响应须为 `{rows,total}`。`headers` 只从服务器身份和密钥取得上游凭据，不转发浏览器 Cookie 或请求头。省略 `editURL` 就只开放查询，此时上游不需要 ETag；启用编辑时，上游分页和修改响应都必须带强 ETag，冲突须返回 412。将同一 `handler` 挂在宿主同源路由即可。

若由宿主直接实现 `repository`，`page({identity,tableId,query})` 必须在同一数据库快照中返回 `{rows,total,revision}`；`edit({identity,tableId,id,field,value,revision})` 必须在一个事务中比较版本、更新该租户及表内的记录并返回新 `{revision}`，冲突抛出 `TableHTTPError(412, '数据版本冲突')`。版本使用带双引号的强 ETag，如 `"42"`。内核校验来源、身份结果、分页参数、字段类型、请求大小与版本头，但目标业务接口、会话验证及租户授权仍由宿主提供。切勿仅凭页面传来的记录 ID 或 Origin 认定用户有写入权限。

接口数据需要给特定记录着色时，在「指定行配色」填写稳定的匹配字段（例如 `id`），新增配色后选择「字段值」并填写该记录的字段值。匹配值按文字比较，数字 `12` 填写 `12`；缺失该字段的记录使用普通行色。相同字段值会共用颜色，因此数据源应提供唯一值。旧版按行号配色仍可用，但服务端分页换页后会按当前页内行号重新应用。字段值配色优先于同一位置的行号配色，单元格条件样式仍优先于整行配色。
